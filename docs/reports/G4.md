## 3. Workflow 租约证据

`run_task.txt` 显示：

```text
task_type=RUN_DISPATCH
status=DONE
attempt=1
lease_token=1
```

任务完成后 `lease_owner` 被清空、`lease_expires_at` 为 NULL，这是 RunTaskQueue Ack 的正常结果。  
`lease_token=1` 证明本次执行经过一次领取与 fencing。

## 4. 事件表快照

`run_events.txt`：

```text
1       | 2   | daemon | MESSAGE_COMPLETED | {"role":"assistant","content":"hello m1 e2e"}

```

主键 `(run_id, attempt, seq)` 连续，最终状态 completed。

## 5. 重跑脚本

```sh
make m1-e2e
```

脚本会自动：

1. 执行迁移
2. 启动 Middleware 和 Harness
3. 创建 echo run
4. 等待终态
5. 校验事件 seq/type/status
6. 记录 run_tasks / run_events 快照
7. 停止进程

## 6. M1 验收结论

**功能 Gate 通过。**

理由：

- App HTTP 创建 Run 成功。
- Run 进入 Workflow 队列并被 Control 领取。
- TaskAssign 下发到真实 Harness。
- Harness echo 返回固定消息。
- 事件落 PostgreSQL。
- Run 状态完成，事件可通过 HTTP 回放。
- 一条命令可重跑并产出证据。
