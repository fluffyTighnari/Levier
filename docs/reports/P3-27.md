## 3. 关键设计

### 3.1 注入式 provider 与工具执行器

- `ReactStrategy(provider, tools)`：
  - `provider` 实现 `async complete(messages, tools) -> LLMResponse`
  - `tools` 实现 `async __call__(ctx, call, timeout_ms) -> ToolResult`
- P3-28 提供真实 provider；P3-29 提供 RuntimeChannel 工具桥。
- 默认工具执行器返回 `TOOL_NOT_AVAILABLE`，保证没有工具桥时行为可控。

### 3.2 消息模型

`Message` 字段：

- `role`
- `content`
- `name`
- `tool_call_id`
- `tool_calls`

`TaskAssign.input` 的 `ChatMessage` 转换为 `Message`。每轮追加：

- assistant 消息（文本 + tool_calls）
- 每个工具调用的 tool 消息（`tool_call_id`、`name`、结果 JSON）

### 3.3 step 循环

```text
for step in 1..max_steps:
  检查取消
  调用 provider（可带 step_timeout_ms）
  USAGE（如有）
  MESSAGE_COMPLETED（有文本或 tool_calls）
  若无 tool_calls → completed
  对每个 tool_call：
    TOOL_CALL_BEGIN
    执行工具
    TOOL_CALL_END
    tool 消息回灌
超过 max_steps → ERROR(MAX_STEPS_EXCEEDED) → failed
```

### 3.4 参数

- `strategy_params.max_steps`：默认 32，最小 1。
- `strategy_params.step_timeout_ms`：默认 120000；`<= 0` 表示不设超时。
- `TaskAssign.timeouts.tool_timeout_ms`：默认 60000，传给工具执行器。

### 3.5 事件

| 事件 | 内容 |
|---|---|
| `MESSAGE_COMPLETED` | `message_id`、`role=assistant`、`content`、`step`、可选 `model`、可选 `tool_calls` |
| `TOOL_CALL_BEGIN` | `invocation_id`、`tool_name`、`arguments_json` |
| `TOOL_CALL_END` | `invocation_id`、`tool_name`、`ok`、`duration_ms`、结果或错误 |
| `USAGE` | provider 返回的用量字段 |
| `ERROR` | `code`、`message` |

`invocation_id` 由 daemon 生成，不复用 provider 的 `call_id`。provider 的工具调用 ID 只用于对话回灌。

### 3.6 错误映射

| 情况 | code | 结果 |
|---|---|---|
| step 超时 | `STEP_TIMEOUT` | failed |
| provider 异常 | `LLM_ERROR` | failed |
| 超过 max_steps | `MAX_STEPS_EXCEEDED` | failed |
| 工具异常 | `TOOL_EXEC_ERROR` | 作为工具结果回灌，循环继续 |
| 工具未接线 | `TOOL_NOT_AVAILABLE` | 作为工具结果回灌，循环继续 |
| 取消 | 无 ERROR | cancelled |

## 4. 验证

```sh
make harness-test
PYTHONPATH=harness/src/gen:harness/src .venv312/bin/python -m unittest harness.tests.test_react -v
make lint
make test
make build
make proto-check
```

结果：

- 7 个 ReAct 测试通过。
- 全部 Python 测试 32 个通过。
- 无工具响应事件顺序：`RUN_STATUS` → `USAGE` → `MESSAGE_COMPLETED` → `RUN_STATUS`。
- 工具闭环事件顺序：`RUN_STATUS` → `MESSAGE_COMPLETED` → `TOOL_CALL_BEGIN` → `TOOL_CALL_END` → `MESSAGE_COMPLETED` → `RUN_STATUS`。
- `max_steps=2` 时只调用两次 provider，随后 `ERROR(MAX_STEPS_EXCEEDED)`、`RUN_STATUS failed`。
- step 超时、provider 异常均产生对应 `ERROR`。
- 取消能中断阻塞中的 provider，最终事件为 `RUN_STATUS cancelled`。
- Go 侧 lint/test/build/proto-check 全绿。
