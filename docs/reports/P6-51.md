## 3. Hello 对账

Hub Hello 注册成功后触发：

```go
OnHello(DaemonInfo)
```

Control `ReconcileDaemon` 读取：

```text
runs WHERE assigned_daemon_id = daemon AND status IN (assigned, running)
```

并对比 `Hello.running_runs`。

## 4. §12.2 对照

| MW 认为 | Daemon 实际 | 实现 |
|---|---|---|
| running 于该 daemon | 不存在 | `RequeueRun`，lease_epoch++，入队 RUN_RETRY |
| 终态 | 仍在跑 | 发送 `Reconcile{cancel_run_ids}` |
| running 于该 daemon | 仍在跑，epoch 一致 | 不动作 |
| running 于该 daemon | 仍在跑，epoch 不匹配 | 发送 Reconcile 取消旧执行 |

Daemon 报告了 MW 不认识的 run：

- 也加入 `Reconcile.cancel_run_ids`
- 防止 daemon 继续跑已终止/已重新分配的 Run

## 5. Daemon lost

Hub `OnOffline` → Control `HandleDaemonOffline`：

1. 查该 daemon 的 assigned/running runs
2. `RequeueRun`
   - `status=queued`
   - `lease_epoch++`
   - 清空 `assigned_daemon_id/assigned_at`
3. 释放本地容量预留
4. 取消 pending local tool
5. 入队 `RUN_RETRY`

下一次 Control 分配时 `attempt++`，并写入新的 `lease_epoch`。

## 6. MW 重启

- Workflow 中的 queued/assigned/running 任务仍在 PostgreSQL。
- Daemon 重连后 Hello 带 `running_runs`。
- Control 在 Hello 回调中逐 run 对账。
- 不依赖 MW 活跃内存状态。
- 未重连 daemon 的 running runs 由 RUN_TIMEOUT / 后续运维对账收敛。

## 7. Lease fencing

- Requeue 时 `lease_epoch++`
- 下一次 TaskAssign 使用新 epoch
- 旧 daemon 事件因 epoch 不匹配被 RunStore/Control 丢弃
- 重连对账发送 Reconcile 取消旧执行
- 避免同一 Run 双执行写状态

## 9. 风险与未完成

| 项 | 影响 | 处理 |
|---|---|---|
| 正常断线也会 requeue | 短暂网络抖动可能造成重试 | 依赖 epoch fencing/Reconcile |
| 没有 MW 启动时主动扫描 | 依赖 daemon 重连或 timeout | P6/P8 |
| Reconcile 只处理 running/assigned | queued 由任务队列处理 | 设计如此 |
| 没有 attempt 上限判断 | 可能持续重投 | P6/P8 |
| Reconcile 发送失败只记录 | daemon 可能继续跑 | 后续重连/对账 |
| local tool 重试没有结果缓存 | 可能重复 App 执行 | P7 幂等 |
| 对账没有持久审计 | 只有控制面日志 | P8 |
