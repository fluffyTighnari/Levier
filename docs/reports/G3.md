## 5. Checkpoint 恢复演示

命令：

```sh
PYTHONPATH=harness/src/gen:harness/src \
  harness/.venv/bin/python -m unittest \
  harness.tests.test_checkpoint_resume -v
```

演示内容：

1. 第一次 React run（session_id 非空）完成，保存 checkpoint：
   - `step=1`
   - messages 包含 user + assistant("first")
   - `last_event_attempt/seq`
2. 第二次 run 使用 `resume_from`，attempt=2：
   - provider 收到恢复后的 messages
   - 只产生新的 `MESSAGE_COMPLETED("second")`
   - 不重复发送 `"first"`
3. echo 恢复：
   - 第二次 run 不再重复 `MESSAGE_COMPLETED`
4. normal runtime：
   - 有 `session_id` 也不写 checkpoint
   - 带 `resume_from` 被拒绝

## 7. 已知缺口

| 缺口 | 影响 | 后续 |
|---|---|---|
| 没有真实 Go Middleware RuntimeService | 无法做真实 App→MW→Harness 全链路 | P4 |
| 没有 Tool Gateway 服务端 | local/global 工具只有 Harness 客户端 | P4/P7 |
| SSE/HTTP MCP 未连真实 server | 网络/认证路径未覆盖 | 后续集成测试 |
| Docker 不可用 | 镜像未实际构建 | 有 Docker 环境时执行 `make image-harness image-mcp-runtime` |
| checkpoint 周期触发只有上下文级测试 | React 20 事件/60s 触发未做长跑 | P3 后续或 P5 |
| Middleware 尚未存 checkpoint | resume_from 只有 Harness 侧 | P5/P9 |
| Runtime 单连接串行处理 | 多 session 并发可能排队 | 后续优化 |
