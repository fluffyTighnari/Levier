## 3. 取消

### HTTP

```http
POST /api/v1/runs/{run_id}/cancel
```

- App/Admin 鉴权 + Run 归属校验
- 可选 body `{"reason":"user"}`

### Control.CancelRun

1. 读 Run；终态直接返回
2. 如果已分配 daemon：
   - 发送 `Cancel{reason}`
3. `Transition(current → cancelled)` CAS
4. Release 容量
5. 取消 active `run_tasks`
6. 取消该 Run 的 pending local tool
7. 发 `run_completed(cancelled)`

queued 状态没有 daemon，只做 CAS 与任务取消。

## 4. run_timeout

创建 Run 时同时入队：

```text
RUN_DISPATCH   now
RUN_TIMEOUT    now + run_timeout_ms
```

Control 处理 `RUN_TIMEOUT`：

1. 读 Run；终态直接 Ack
2. 已分配则发送 Cancel
3. `Transition(current → timeout)`
4. Release 容量
5. 取消 pending local tool
6. 发 `run_completed(timeout)`

Run 正常完成时：

- Control 取消仍 active 的 `RUN_TIMEOUT`
- 避免超时任务长期占用

## 5. 取消 / 完成竞态

- 状态迁移全部走 CAS
- 取消先到：`cancelled` 终态
- 完成先到：`completed` 终态
- 后到事件只落事件，不改变终态
- 测试验证 late completion 不会覆盖 cancelled

## 6. 挂起本地工具

`AppHub.CancelLocalTools(appID, runID, code, message)`：

- 按 App + Run 找到 pending local tool
- 返回错误结果给等待方
- pending 移除

Cancel/Timeout 都会触发。

## 8. 风险与未完成

| 项 | 影响 | 处理 |
|---|---|---|
| 取消先 Transition，再等 daemon | daemon 可能晚到 Cancel | epoch/终态守卫 |
| timeout 当前任务可能被取消 | Worker Ack 可能 lease lost | 终态已写，可接受 |
| 取消任务与当前任务同一队列 | `CancelRun` 可能取消自身 | P6/P8 细化 |
| 没有取消重试 | Cancel 丢包依赖 daemon 断线/对账 | P6-51 |
| 没有 per-run 取消审计 | 只靠事件 | P8 |
| 没有 run_timeout 抖动/上限 | 长/短超时直接使用 | P5/P8 |
| 本地工具取消只在本进程 | 多实例不共享 | P8 |
