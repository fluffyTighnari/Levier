## 3. 关键决策

- 指标不引入外部依赖，使用 `atomic.Int64` 实现进程内 Snapshot；后续 P8-62 接 Prometheus/OTel。
- 队列深度/最老年龄由 `Store.Stats` 提供，`Pool.Stats` 代理；不在 worker 内轮询数据库。
- Ack/Nack/Fail/Dead/LeaseLost/Panic 都在 worker 结果路径计数。
- Claim/Handler 平均耗时按成功处理的次数计算。
- 基准测试只在设置了 `MIDDLEWARE_TEST_POSTGRES=1` 时运行。

## 4. 验证

```sh
MIDDLEWARE_TEST_POSTGRES=1 go test -count=1 -v -timeout 120s ./internal/workflow
make lint
make test
make build
make proto-check
MIDDLEWARE_TEST_POSTGRES=1 go test -run '^$' -bench 'Benchmark(Enqueue|ClaimAck)$' -benchtime=100x ./internal/workflow
```

结果：

- 指标单测通过；Worker Ack 后 Claims/Handled/Acks 均为 1。
- Pool Stats 返回 total=8、done=8。
- 全量真实 PostgreSQL 测试通过。
- `-benchtime=100x` 通过 SSH 隧道测得：
  - `BenchmarkEnqueue`：约 35.6 ms/op（约 28/s）
  - `BenchmarkClaimAck`：约 71.2 ms/op（约 14/s）
  - 这两个数字受 SSH 隧道 RTT 主导，**不能作为 1k/s 目标的结论**。
