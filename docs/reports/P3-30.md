## 3. 关键设计

### 3.1 Checkpoint 内容

```json
{
  "version": 1,
  "session_id": "...",
  "run_id": "...",
  "attempt": 2,
  "strategy": "react",
  "step": 7,
  "messages": [],
  "last_event_attempt": 2,
  "last_event_seq": 42,
  "created_at": "..."
}
```

- 对 Middleware 不透明。
- `messages` 包含文本、tool call、tool result。
- `last_event_attempt` + `last_event_seq` 是复合 watermark。
- 版本不匹配、JSON 损坏、字段缺失均拒绝。

### 3.2 上报

- `RunContext.save_checkpoint()` 更新 attempt/seq。
- `EventWriter.emit_checkpoint()` 发送 `Checkpoint` Envelope。
- 随后发送持久化 `CHECKPOINT_SAVED` 事件。
- 触发条件：
  - 每 20 条持久化事件；
  - 每 60 秒；
  - 取消时；
  - 终态安全点。

### 3.3 恢复

- `RunManager` 在 TaskAck 前解码 `resume_from.state`。
- 校验：
  - checkpoint run_id
  - session_id
  - strategy
  - 缺失 `session_id` 时拒绝
- `ReactStrategy`：
  - 恢复 messages；
  - 从 `checkpoint.step + 1` 继续；
  - 不重发旧消息；
  - 新 attempt 的 seq 从 1 开始。
- `EchoStrategy`：
  - 有 checkpoint 时直接完成，不重复 echo。
