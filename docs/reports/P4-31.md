## 4. API 行为

### CreateRun

- 校验 `run_id`、`app_id`、JSON 参数。
- 默认：
  - `status=queued`
  - `runtime=normal`
  - `strategy=react`
  - `run_timeout_ms=1800000`
  - `trace_id=run_id`
- 有 `idempotency_key` 时：
  - 同 key + 同 `request_hash` 返回已有 Run。
  - 同 key + 不同 `request_hash` 返回 `ErrIdempotencyConflict`。
- 不创建 `run_tasks`；调度任务由 P4-33 Control 负责。

### GetRun

- 按 `run_id` 查询。
- 不存在返回 `ErrRunNotFound`。
- 返回事件水位 `last_event_attempt` / `last_event_seq`。

### AppendEvent

- 校验 `attempt >= 1`、`seq >= 1`、`source in (daemon,mw)`、type 非空、payload 是合法 JSON。
- 事务内：
  - `INSERT ... ON CONFLICT (run_id, attempt, seq) DO NOTHING`
  - 仅插入成功时更新 `runs.last_event_*`
- 重复事件返回 `inserted=false`，不重复写。
- 旧 attempt/seq 不会把 Run 投影水位回退。

## 6. 风险与未完成

| 项 | 影响 | 处理 |
|---|---|---|
| runs.app_id 暂无 FK | 可以写入不存在的 app | P5 完整 Register 时补约束/校验 |
| 没有 `ListEvents` | HTTP 事件回放还未接 | P4-34 |
| 没有 Run 状态迁移方法 | Control 还没有接 | P4-33 |
| 没有 RunTask 入队 | 创建 Run 后不会自动调度 | P4-33 |
| idempotency 竞态只重试两次 | 极端并发可能返回错误 | 后续可用 `INSERT ... ON CONFLICT` + 单查询优化 |
| 事件连续性不校验 | 允许 seq gap | P4-34/P5 事件校验 |
| JSONB 会规范化空白 | 字符串比较不可靠 | 测试按 JSON 语义比较 |
| 没有迁移回滚 | 本地开发回退需手工 | 后续可加 down 脚本 |
