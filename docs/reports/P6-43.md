## 3. 生命周期

### Hello

- 首个 Envelope 必须在 `HelloTimeout`（默认 3s）内到达。
- 首包必须是 Hello。
- Envelope 形状由 `protocol.Validate` 校验。
- token 错误返回 `Unauthenticated`。

### 重复 daemon_id

策略：拒绝新连接。

- 旧连接保持。
- 新连接返回 `AlreadyExists`。
- 旧连接仍可接收 `Send`，不会双写。

### labels / strategies

- Hello 中保存：
  - `runtime_type`
  - `max_concurrent_runs`
  - `supported_strategies`
  - `labels`
- `PickHealthy` 过滤：
  - runtime type
  - strategy
  - labels 超集
  - max concurrency
- 选择 running/max 最低。

### 优雅关闭

`Hub.Close()`：

1. 标记 hub closed
2. 清空注册表
3. 关闭每个连接的 `done`
4. 等待所有 Channel handler 退出
5. 最多等待 `CloseTimeout`（默认 5s）

`readLoop` 现在可被 `done` / stream context 取消，不再只依赖客户端断开。

关闭后：

- `Send` 返回 `ErrHubClosed`
- 新 `Channel` 返回 `Unavailable`

## 5. 风险与未完成

| 项 | 影响 | 处理 |
|---|---|---|
| 没有主动心跳死亡清理 | 断网但 stream 未断的 daemon 仍可能在 map | P6-45 |
| readLoop 每次 Recv 一个协程 | 连接关闭后可能有短生命周期 goroutine | stream 关闭后回收 |
| writeLoop 仍可能阻塞在 stream.Send | 慢消费者需要背压策略 | P6-44 |
| 重复 ID 直接拒绝 | 半死连接会拒绝新连接 | P6-45 stale reaper |
| 没有 TLS/mTLS | 内网可信假设 | P8/P10 |
| `Close` 只保证 handler 退出 | 不负责关闭底层 gRPC listener | main 负责 Stop |
