## 1. 目标

消除“Run 已落库、dispatch/timeout 没入队”的孤儿窗口：

```text
创建 Run
+ Enqueue(RUN_DISPATCH)
+ Enqueue(RUN_TIMEOUT)
= 一个 PostgreSQL 事务
```

任一步失败，整体回滚。

## 2. 改动

### 2.1 runstore

新增：

```go
type TxFunc func(ctx context.Context, tx pgx.Tx, run Run) error

func (s *Store) CreateRunWithTx(ctx context.Context, run Run, after TxFunc) (Run, error)
```

行为：

```text
normalize run
→ Begin
→ createRun(tx)
→ after(ctx, tx, created)
→ Commit
```

`after` 返回错误 → Rollback；`created` 是新建或幂等返回的已有 Run，
闭包必须用它来生成任务 RunID。

`CreateRun` 保留原路径，内部复用 `createRun`。

### 2.2 HTTP API

新增可选接口：

```go
type transactionalRunStore interface {
    CreateRunWithTx(ctx, run, after) (runstore.Run, error)
}

type transactionalTaskQueue interface {
    EnqueueTx(ctx, tx, task) (workflow.Task, error)
}
```

当 `s.runs` 和 `s.queue` 都支持事务时：

```text
CreateRunWithTx
  → if created.status == queued
      EnqueueTx(RUN_DISPATCH)
      EnqueueTx(RUN_TIMEOUT)
```

否则回退到旧路径，保持 fake/测试实现兼容。

错误映射：

```text
enqueue 失败 → 503 QUEUE_UNAVAILABLE
idempotency conflict → 409
invalid run → 400
其他事务错误 → 当前保持 500/503 由调用处决定
```

## 5. 风险

| 项 | 影响 | 处理 |
|---|---|---|
| fake store/queue 不支持事务 | 单元测试仍走旧路径 | 生产实现支持事务；旧路径保留兼容 |
| 事务错误分类较粗 | 队列/DB 错误都可能是 503/500 | MVP 先保证不产生孤儿；后续细化错误码 |
| 事务内 enqueue 失败会回滚 Run | 客户端必须用同一 Idempotency-Key 重试 | 503 retryable；R18 启动恢复仍兜底 |
| 大事务持锁时间 | 单机 MVP 可接受 | 后续压测再评估 |
