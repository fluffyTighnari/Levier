## 3. 关键决策

- TaskAck 在创建 RunContext 前发送，避免策略执行延迟 Ack。
- 校验项：
  - Envelope.run_id == TaskAssign.run_id
  - run_id、app_id、strategy 非空
  - strategy 在支持列表
  - attempt >= 1
  - lease_epoch >= 1
  - 未处于 draining
- 容量按 `len(active)` 判断，超限拒绝 `reason=capacity`。
- 同 run_id + 同 lease_epoch 的重复 TaskAssign 返回 accepted=true，不重复启动。
- 同 run_id + 不同 lease_epoch 拒绝，避免旧/新执行代次混用。
- 接受后发送 `RUN_STATUS running`，再启动异步 runner。
- runner 返回后发送终态 `RUN_STATUS`；取消优先覆盖为 `cancelled`。
- Cancel 和 Reconcile 都设置 cancel_event 并取消 task。
- `close()` 取消所有活跃 Run 并等待任务结束。
- NoopRunner 只返回 completed，P3-26 替换为 echo。

## 4. 验证

```sh
make harness-test
PYTHONPATH=harness/src/gen:harness/src .venv312/bin/python -m unittest discover -s harness/tests -v
make lint
make test
make build
make proto-check
```

结果：

- 23 个 Python 测试全部通过。
- TaskAssign 接受后事件序列为 `running` → `completed`，seq 为 1、2。
- TaskAck correlation 等于 TaskAssign 的 msg_id。
- 未知 strategy、容量不足被拒绝。
- 重复 TaskAssign 不重复启动。
- Cancel / Reconcile 后最终事件为 `cancelled`。
- `close()` 能取消活跃 Run。
- 正常启动 SIGTERM 后退出码 0。
