## 1. 目标

让同一个 `invocation_id` 的工具调用只执行一次，并让重复请求得到同一结果：

- 进程内 single-flight：并发重复请求挂到同一个 future。
- 结果缓存：完成后直接返回，TTL 到期后淘汰。
- PostgreSQL `tool_invocations`：跨进程认领与结果持久化。
- 崩溃遗留的 `in_flight` 记录可在过期后接管。
- 不改变 P7-52 的 `Invoker` 调用方式。

## 3. 调用流程

```text
Invoke(request)
  │
  ├─ 参数校验
  ├─ 进程内缓存命中 ──► 返回缓存结果
  ├─ 已有 in-flight future ──► 等待同一 future
  │
  └─ 成为 owner
       ├─ store.Begin(invocation_id, run_id, tool_name)
       │    ├─ 认领成功 ──► invokeOnce
       │    ├─ 已有终态 ──► 缓存并返回
       │    └─ 他人在跑 ──► TOOL_EXEC_ERROR(retryable=true)
       ├─ invokeOnce（P7-52 路由）
       ├─ store.Complete / store.Fail
       ├─ 写入进程内缓存
       └─ 发布结果给等待者
```

## 4. Single-flight

- 以 `invocation_id` 为键。
- owner 创建 `flight{done chan struct{}}`；重复请求返回同一 `flight` 并等待。
- owner 完成后先写缓存，再删除 flight 并关闭 channel。
- 等待者读取的是结果副本，不能修改共享状态。
- 等待者上下文取消时返回 `TOOL_TIMEOUT(retryable=true)`，不会写缓存。

## 5. 结果缓存

| 项 | 默认值 |
|---|---|
| TTL | 5 分钟 |
| 容量 | 1024 条 |
| 内容 | 终态结果（成功与非重试失败均缓存） |

- 过期条目在读写时淘汰。
- 容量满时淘汰一条任意条目。
- 缓存只是快速路径，PostgreSQL 是权威来源。
- 可通过 `WithResultCache(ttl, maxEntries)` 调整。

## 6. PostgreSQL 幂等

`tool_invocations` 使用：

```text
invocation_id (PK), run_id, tool_name, status,
result_json, error_json, created_at, completed_at
```

`Begin`：

1. `INSERT ... ON CONFLICT DO NOTHING` 认领新 invocation。
2. 若已存在，尝试接管超过 `staleAfter`（默认 5 分钟）的 `in_flight` 记录。
3. 否则读取终态；终态返回结果，`in_flight` 返回 busy。

`Complete` / `Fail`：

- 只在 `status='in_flight'` 时更新，避免终态被覆盖。
- 失败结果以 `{code,message,retryable}` 写入 `error_json`。

## 7. 错误语义

| 情况 | code | retryable |
|---|---|---|
| 等待中的请求被取消 | `TOOL_TIMEOUT` | true |
| 其他进程正在执行同一 invocation | `TOOL_EXEC_ERROR` | true |
| 存储读写失败 | `TOOL_EXEC_ERROR` | false |
| 缓存命中 | 原结果 | 原值 |

失败终态会随 `invocation_id` 缓存，重复请求不会重新执行。这是 effectively-once 的选择：重试复用它来取回已产生的结果，而不是再次产生副作用。

## 8. 测试

## 9. 风险与未完成

| 项 | 影响 | 处理 |
|---|---|---|
| 缓存与 in-flight 状态是单进程内存 | 多实例时只由 PostgreSQL 串行化 | 已用 DB 认领；多实例压测留 P8 |
| 失败结果也会缓存 | 可重试错误在 TTL 内不会重新执行 | 符合 effectively-once；如需重试新 invocation_id |
| 过期接管没有 fencing token | 极旧 owner 完成后可能覆盖新结果 | 仅在崩溃恢复窗口出现；P8 可加 claim token |
| owner 的上下文取消会中止共享执行 | 先到调用者的超时影响等待者 | Control 当前使用 background 上下文 |
| 缓存无指标 | 命中率不可观测 | P8 指标 |
| 没有 invocation 清理策略 | 表会持续增长 | P8/P9 GC 或归档 |
| local 结果缓存不区分 App | 依赖 invocation_id 全局唯一 | 协议已要求 MW 生成 |
