## 3. 关键决策

- Fake daemon 是 **client-side** 测试工具，用于驱动 middleware 的 gRPC server；不是生产代码。
- `Config` 可控制 `Accept`、`RejectReason`、`AckDelay`、`AutoEcho`、`SkipHello`、`HeartbeatInterval`、`DisconnectAfterAssignments`。
- `Send` 统一走 `internal/protocol.Validate`，确保测试不会发送非法 Envelope。
- `AutoEcho` 发送持久事件：`RUN_STATUS running` → `MESSAGE_COMPLETED` → `RUN_STATUS completed`，seq 从 1 递增。
- `RequestTool` 使用 `invocation_id` 挂起等待 `ToolCallResult`，支持工具闭环测试。
- `OnMessage` 可替换默认 TaskAssign 处理，用于脚本化故障/自定义行为。
- `Assignments()` / `Events()` 提供观察通道，便于测试断言。

## 4. 验证

```sh
go test ./internal/testutil/fakedaemon
make lint
make test
make build
make proto-check
```

结果：

- AutoEcho 测试：Hello → TaskAck accepted → 3 个事件，seq 连续。
- Reject 测试：TaskAck accepted=false + reason。
- RequestTool 测试：ToolCallRequest → ToolCallResult 闭环。
- 断线测试：daemon 在 TaskAssign 后断开，测试 server 收到 EOF。
- `make lint/test/build/proto-check` 全绿。
