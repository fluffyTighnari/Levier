## 3. 调度流程

```text
workflow.Worker.Claim(RUN_DISPATCH)
  → Control.Handle
  → RunStore.GetRun
  → DaemonHub.PickHealthy(runtime, strategy, labels)
  → RunStore.AssignRun(attempt, lease_epoch, daemon)
  → 组装 TaskAssign
  → DaemonHub.Send
  → 等待 TaskAck（默认 5s）
  → accepted=true：Worker Ack 任务
  → accepted=false/超时：Worker Nack，按退避重投
```

状态：

```text
queued
  → assigned（发送前写入）
  → running（收到 RUN_STATUS running）
  → completed / failed / cancelled / timeout
```

## 4. TaskAssign 组装

来源：

- `runs.run_id` / `app_id`
- `runs.runtime` / `strategy`
- `runs.params_json` → `strategy_params`
- `runs.input_json` → `repeated ChatMessage`
- `runs.model_json` → `ModelProfile`
- `runs.run_timeout_ms` / `tool_timeout_ms`
- `runs.session_id`
- `runs.trace_id`

v1 最小 Control 暂不下发：

- `tools`
- `mcp_bindings`
- `resume_from`

这些留给 Register/工具与 longterm 接线。

## 5. TaskAck

- Control 以 `TaskAssign.msg_id` 建 pending channel。
- `HandleEnvelope` 按 `correlation_id` 交付 `TaskAck`。
- 接受：任务 Ack。
- 拒绝或 5s 超时：返回 workflow retry error，任务 Nack。
- 旧 daemon 的事件由 `attempt + lease_epoch` fencing 丢弃。

## 6. 事件消费

- DaemonHub 入站 Event → Control 事件缓冲。
- 校验 `attempt` 与 `lease_epoch` 与当前 Run 一致。
- `RunStore.AppendEvent` 幂等写入。
- `RUN_STATUS` 驱动状态：
  - running
  - completed
  - failed
  - cancelled
  - timeout
- stale epoch/attempt 的事件不落库、不更新状态。

## 7. 入口接线

`cmd/middleware` 现在：

- 启动 DaemonHub gRPC
- 创建 RunStore
- 创建 Control
- 把 `Control.HandleEnvelope` 挂到 Hub
- 启动 workflow worker pool
- SIGTERM 时依次停止 worker、Control、Hub、gRPC

## 9. 风险与未完成

| 项 | 影响 | 处理 |
|---|---|---|
| TaskAck 超时后未主动 Cancel | 旧 daemon 可能继续执行 | 依赖 lease_epoch fencing；后续补 Cancel |
| 没有 RunTimeout 任务 | 长跑不会被 Control 强制终态 | P4-36/P5 |
| 没有 Reconcile | 重连 daemon 的 running_runs 未对账 | P6 |
| 没有 attempt 上限判断 | 可能无限重投 | P5/P6 |
| 没有 tools/mcp_bindings/register 材料 | TaskAssign 还没有真实工具 | P5/P7 |
| 没有 checkpoint resume_from | longterm 恢复未接 Control | P5/P9 |
| 没有 labels 调度输入 | Run 级 labels 未建模 | P5/P6 |
| 事件缓冲满会丢弃 | 极端负载可能丢事件 | P6/P8 背压 |
| 旧 daemon 事件直接忽略 | 没有 Cancel/审计 | P6 对账 |
| `AssignRun` 没有 attempt 上限 | 需要后续状态机约束 | P5/P6 |
