## 3. ws_token

- `POST /runs` 成功后签发短期 token。
- 默认 TTL 10 分钟。
- token 绑定 app_id。
- 内存存储；v1 单实例。
- 响应：

```json
{"run_id":"...","status":"queued","ws_url":"/api/v1/ws","ws_token":"..."}
```

## 4. WebSocket 连接

```text
GET /api/v1/ws?app_id=<app>&token=<ws_token>
```

校验：

- token 存在
- token 未过期
- token.app_id == query.app_id

失败直接关闭连接。

## 5. AppHub

- `Register(appID, sink)`：注册连接。
- `Subscribe(runID)`：订阅 run。
- `Publish(appID, runID, payload)`：
  - 只发给该 App 下订阅了该 run 的连接。
  - fanout 到多连接。
- `CloseConn`：单个连接断开清理。
- `Close`：关闭全部。

## 6. WS 消息

### subscribe

- 校验 run 存在。
- 校验 run.app_id == 当前 App。
- 跨 App 订阅返回 `RUN_NOT_FOUND`。
- 从 `last_attempt/last_seq` 回放事件。
- 回放完成发 `caught_up`。

### ping

- 返回 `pong`。

### hello

- v1 可选，接受并忽略。

### local_tool_result

- P6-47 再接挂起表和结果路由。

## 7. Control fanout

Control 在事件幂等写入后：

- 构造 `event` JSON
- 调用 `Publisher.Publish(appID, runID, payload)`

终态事件额外发：

```json
{"type":"run_completed","run_id":"...","status":"completed","attempt":1}
```

## 9. 风险与未完成

| 项 | 影响 | 处理 |
|---|---|---|
| ws_token 只存内存 | 多实例/重启不共享 | P6/P8 |
| token 没有主动清理 | 内存会增长 | 后续 GC |
| WS 没有写队列/背压 | 慢 App 会阻塞 fanout | P6-47/P8 |
| local_tool_result 未处理 | 工具闭环未接 | P6-47 |
| subscribe 回放上限 1000 | 更多需要分页 | P7 |
| 没有 heartbeat/ping 定时 | 连接活性依赖 TCP | P7/P8 |
| 没有 WS 指标 | 观测不足 | P8 |
| 回放与实时订阅有竞态 | 可能重复/乱序 | 后续用 seq 去重 |
