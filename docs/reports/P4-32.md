## 3. 关键设计

### 3.1 Hello 与鉴权

- 连接建立后必须在 `HelloTimeout`（默认 3s）内发送 `Hello`。
- 首包不是 Hello、Envelope 非法或鉴权失败都会关闭 stream。
- 鉴权使用 `grpc.daemon_tokens`：

```yaml
grpc:
  daemon_tokens:
    daemon-local-1: "change-me"
```

- 比较使用 `crypto/subtle.ConstantTimeCompare`。
- 未配置 token 的 daemon 一律拒绝。

### 3.2 重复 daemon_id

策略：**拒绝新连接**。

- 同一 `daemon_id` 已有 active stream 时，新连接返回 `codes.AlreadyExists`。
- 旧连接保持，避免重连抖动导致两个流同时写入。
- 旧连接断开后，daemon 可以重新连接。

### 3.3 心跳

- 收到 `Heartbeat` 更新 `LastHeartbeat` 与 `RunningCount`。
- 心跳用于健康判断和 `PickHealthy`。
- 本步只实现心跳更新；主动死亡清理留给后续 Control/对账。

### 3.4 出站发送

- 每个 daemon 一个有缓冲 `sendCh`，默认容量 256。
- 单写 goroutine 串行调用 `stream.Send`。
- 缓冲满返回 `ErrBackpressure`；daemon 离线返回 `ErrDaemonOffline`。
- 连接关闭使用 `done` channel，避免关闭 send channel 引发竞态。

### 3.5 连接清理

- `Channel` 退出时从 map 删除，仅当 map 中仍是当前连接。
- 清理会关闭 `done`，写 goroutine 退出。
- `Hub.Close()` 标记 hub 关闭并清理所有注册。

### 3.6 PickHealthy

按以下条件选择：

- runtime type 匹配（`UNSPECIFIED` 为通配）
- strategy 在 supported_strategies
- labels 是请求 labels 的超集
- 未超过 max concurrency
- 选择 running/max 比例最低的 daemon

## 4. 入口接线

`cmd/middleware` 现在：

- 连接 PostgreSQL
- 创建 `DaemonHub`
- 在 `grpc.addr` 启动 `RuntimeService`
- 使用 `grpc.max_recv_msg_bytes` / `max_send_msg_bytes`
- SIGTERM 时先关闭 Hub，再优雅停止 gRPC；超时则强制 Stop

## 6. 风险与未完成

| 项 | 影响 | 处理 |
|---|---|---|
| 没有主动心跳死亡清理 | 断网但未断 stream 的 daemon 仍可能在 map | P4-33/Control 或 P8 补 reaper |
| 没有 TLS/mTLS | 依赖内网可信 | 后续安全加固 |
| daemon token 存明文配置 | 配置文件泄露即凭据泄露 | 后续密钥介质/auth_ref |
| 背压只返回错误 | 没有丢 ephemeral/断开慢消费者 | P6/P8 完整策略 |
| 入站事件只回调 `OnEnvelope` | 还没有 RunStore/Control 消费 | P4-33/P4-35 |
| `OnEnvelope` 当前为 nil | 事件被验证后丢弃 | P4-33 接 Control |
| 重复 ID 直接拒绝 | 旧连接半死时新连接会被拒 | 客户端退避重试；后续加 stale reaper |
| gRPC 优雅关闭可能等待客户端 | 超时后强制 Stop | 已有 10s 兜底 |
