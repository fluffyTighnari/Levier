## 1. 目标

事件缓冲满时，普通事件可以丢，但终态和错误事件不能静默丢：

```text
普通事件      立即丢弃 + 指标 + 日志
终态 RUN_STATUS / ERROR
              短等待 → 仍满 → 记录 critical
              → requeue daemon 的 active runs
              → 断开 daemon，旧执行由新 epoch fencing
```

## 2. 改动

### 2.1 可配置缓冲

`workflow.event_buffer`：

```yaml
workflow:
  event_buffer: 256
```

支持 `MIDDLEWARE_WORKFLOW_EVENT_BUFFER`，校验必须为正数。
`cmd/middleware/main.go` 把它传给 `control.Config.EventBuffer`。

### 2.2 关键事件识别

```text
EventType ERROR
EventType RUN_STATUS + status in {completed, failed, cancelled, timeout}
```

`running` 不算关键事件。

### 2.3 入队策略

```text
1. 先非阻塞入队
2. 普通事件失败 → control_buffer_full
3. 关键事件失败 → 等待 CriticalEventWait（默认 500ms）
4. 仍失败 → critical_buffer_full
   → criticalEvents++
   → goroutine:
       HandleDaemonOffline(daemonID)   requeue active runs
       Hub.Disconnect(daemonID)        关闭旧 stream
```

`DaemonHub` 增加：

```go
Disconnect(daemonID string)
```

`Hub.Disconnect` 关闭 `daemonConn.done`，读循环退出后走既有
`remove + OnOffline` 路径。

### 2.4 指标

新增：

```text
mw_event_append_duration_seconds{source}
mw_event_append_errors_total{source}
```

原有：

```text
mw_events_dropped_total{reason="control_buffer_full"}
mw_events_dropped_total{reason="critical_buffer_full"}
```

## 3. 测试

```text
TestCriticalEventIdentifiesTerminalAndError
TestCriticalEventBufferFullDropsDaemon
TestNormalEventBufferFullDropsWithoutDisconnect
TestDisconnectClosesStreamAndFiresOffline
```

断言：

```text
completed/failed/cancelled/timeout/ERROR 为关键
running/MESSAGE_COMPLETED 不是
关键事件满 → criticalEvents=1 + requeue + disconnect
普通事件满 → 不 disconnect
Hub.Disconnect → daemon 移除 + OnOffline
```

## 5. 风险

| 项 | 影响 | 处理 |
|---|---|---|
| 关键事件本身仍未落库 | 该 attempt 的终态丢失，Run 重跑 | normal 语义是 at-least-once；新 attempt 会重新产生终态 |
| 重跑可能重复工具副作用 | 计数器等非幂等工具会重复 | `docs/MVP.md` 已明确；App 按 invocation_id 幂等 |
| DB 持续慢会反复断连 | 抖动 | 指标/日志可见；MVP 单机可接受，后续做背压与慢查询治理 |
| 500ms 等待会短暂阻塞 daemon 读循环 | 心跳延迟 | 只在缓冲满且关键事件时发生；默认值可调 |
