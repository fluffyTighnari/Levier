## 3. 分配流程

```text
Scheduler.Pick
  → Reserve(daemon)
  → AssignRun(assigned, attempt, lease_epoch)
  → 组装 TaskAssign
  → DaemonHub.Send
  → 等 TaskAck（5s）
```

### 接受

- 返回 nil
- Worker Ack 任务
- 预留容量保留到 Run 终态

### 拒绝

- `Release(daemon)`
- 将 daemon 加入 exclude
- 立即尝试下一个候选
- 最多 `MaxPlacementAttempts`（默认 3）

### 超时

- `Release(daemon)`
- 返回普通错误
- Worker 使用 `Backoff` 重投
- 下一次 attempt 会 `attempt++`、`lease_epoch++`

### 发送失败 / AssignRun 失败

- Release 预留
- 返回错误或忽略竞态

## 4. 退避

Control 不再固定返回 `RetryAfter(2s)`，而是返回普通错误。

Worker：

```text
attempt 1 → 2s
attempt 2 → 4s
attempt 3 → 8s
...
max 5min
```

退避曲线由已有的 `workflow.Backoff` 保证。

## 5. 容量预留

DaemonInfo 增加：

```text
Reserved int32
```

Hub：

- `Reserve(daemonID)`：按 `max(RunningCount, Reserved)` 判断
- `Release(daemonID)`：释放一个预留

作用：

- 防止调度选主后、心跳尚未反映前超卖
- 终态事件释放预留
- daemon 断线时连接消失，预留一并清理

## 7. 风险与未完成

| 项 | 影响 | 处理 |
|---|---|---|
| 成功后预留保留到终态 | 若 daemon 永不上报终态，容量暂不释放 | P6-50 超时/P6-51 对账 |
| 拒绝重试使用同一 attempt/epoch | 拒绝 daemon 未执行，可接受 | 超时重投会递增 |
| AssignRun 在发送前写入 | 发送失败会短暂 assigned | 重投时修复 |
| reserved 只在本进程 | 多实例不共享 | P6/P8 |
| 没有 draining 状态 | 可能分配到 draining daemon | P6-50 |
| 没有容量指标 | 观测不足 | P8 |
| `MaxPlacementAttempts` 固定 3 | 大集群可能不够 | 可配置/后续优化 |
