## 3. 入站分发

- Hello：连接建立时处理。
- Heartbeat：
  - 更新 `LastHeartbeat`
  - 更新 `RunningCount`
  - 回调 `OnHeartbeat(daemonID, runningCount)`
- 其他消息：
  - `TaskAck`
  - `Event`
  - `ToolCallRequest`
  - `Checkpoint`
  - `ErrorReport`
  - 统一交给 `OnEnvelope`

所有业务 callback 都经过 `safeCall`：

```text
panic → recover → OnError / 日志
```

panic 不会杀死进程，也不会直接关闭连接。

## 4. 心跳与死亡判定

参数：

```text
daemon 心跳间隔      10s
HeartbeatTimeout     30s
HeartbeatCheckPeriod 5s
```

`Hub.Sweep(now)`：

- 扫描 `last_heartbeat`
- 超过 `HeartbeatTimeout`：
  - 从 map 删除
  - 关闭连接
  - 调用 `OnOffline`
- 后台 reaper 每 5s 调一次 `Sweep(cfg.Now())`

测试使用假 `Now`：

```text
base
base + 31s → Sweep → count=0, OnOffline("daemon")
```

## 5. 容量校准

Heartbeat 的 `running_count` 会覆盖本地 `RunningCount`：

```text
Heartbeat{running_count:3}
→ DaemonInfo.RunningCount = 3
```

用于修正调度计数漂移。

## 7. 风险与未完成

| 项 | 影响 | 处理 |
|---|---|---|
| 心跳计数信任 daemon | 恶意/错误 daemon 可报错误容量 | 后续校验/上下文 |
| `Sweep` 使用墙钟 | 系统时钟跳变会影响死亡判定 | 生产 NTP；后续单调时钟 |
| panic 隔离只保连接 | 业务 handler 可能需要修复/重试 | OnError 监控 |
| 正常断线也触发 OnOffline | 与被动死亡使用同一回调 | 可增加原因参数 |
| reaper 固定 5s | 判死延迟最多约 5s | 可配置 |
| 没有 offline 事件持久化 | 仅 callback | P6/P8 事件模型 |
| 全消息分发仍由同一读循环串行调用 | 慢 handler 会阻塞连接读 | P6/P8 异步化 |
