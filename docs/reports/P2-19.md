## 3. 关键决策

- `ReapExpired` 使用 `FOR UPDATE SKIP LOCKED` 批量扫描 `LEASED AND lease_expires_at <= now`。
- 回收时 `lease_token++`，旧 worker 的 Ack/Extend/Nack/Fail 会 `ErrLeaseLost`。
- `attempt >= max_attempts` 时回收直接进 DEAD；否则回 PENDING，`available_at=now`，`last_error=lease_expired`。
- `limit<=0` 默认 100。
- `Backoff` 从 base 开始指数增长，封顶 max；attempt<=1 返回 base。
- DLQ 用 `status='DEAD'`，不单独建表；`ListDead` 按 `updated_at DESC`。
- `Stats` 返回 total、按状态/类型计数、最老 PENDING 及其年龄。

## 4. 验证

```sh
MIDDLEWARE_TEST_POSTGRES=1 go test -count=1 -v -timeout 120s ./internal/workflow
make lint
make test
make build
make proto-check
```

结果：

- 过期租约回收为 PENDING，旧 lease 写入返回 `ErrLeaseLost`。
- attempt==max 的过期任务回收为 DEAD。
- `limit=2` 分两批回收 3 个过期任务。
- Stats：总数/状态/类型/最老 PENDING 正确。
- ListDead 返回 DEAD 任务。
- Backoff 1/2/3 次及上限正确。
- 真实 PostgreSQL 16.15 通过；默认 `make test` 跳过 DB 测试。
- `make lint/test/build/proto-check` 全绿。

## 5. 风险与未完成

| 项 | 影响 | 处理 |
|---|---|---|
| 启动恢复未扫 Run | 缺少任务的 Run 不会自动补 | P6-51 Control 扫描非终态 Run 并入队 |
| Reap 只返回数量 | 不知道 DEAD/PENDING 各多少 | P2-22 指标可补；或后续返回明细 |
| Backoff 无 jitter | 大量任务同时重试 | Worker 层可加抖动；当前确定性便于测试 |
| Stats 年龄用应用时钟 | 与 DB 时钟可能轻微偏差 | 监控可接受；P2-22 可改用 DB 差值 |
| ListDead 无游标分页 | 大量死信只能截断 | P2-22/运维接口补分页 |
