## 1. 目标

用真实进程而不是 mock 验证 R17/R20/R13/R21 的收敛行为：

```text
Harness kill -9
MW 重启
App 断线
取消
超时
```

## 2. 脚本

新增 `scripts/fault_matrix.py`，Makefile 入口：

```sh
make fault-matrix
```

流程：

```text
build middleware/migrate
→ migrate
→ 启动 Middleware / Harness / Counter App
→ bootstrap App
→ 依次注入故障
→ 每次检查状态、事件、任务
→ 清理进程和凭据
```

输出：

```text
data/fault-matrix/<时间>/
  middleware.log
  harness.log
  app.log
  summary.txt
```

本次证据复制到 `docs/reports/artifacts/P11.9/`。

## 3. 场景与结果

| 场景 | 注入 | 结果 |
|---|---|---|
| harness_kill | 运行中 `kill -9` Harness | requeue，重启后 attempt 2 completed |
| mw_restart | 运行中停 MW，再启动 | Harness 重连，Run completed |
| app_disconnect | 停 App 后提交 Run；再启动 App 提交新 Run | 第一个 Run 有 3 次失败工具调用但收敛；第二个 completed |
| cancel | 提交后立即取消 | cancelled + `source=mw` 事件 + 无 active task |
| timeout | `run_ms=500` | timeout + `source=mw` 事件 + 无 active task |

本次运行：

## 4. 检查项

脚本对每个相关 Run 检查：

```text
终态符合预期
daemon 事件按 attempt 连续（count = max-min+1）
cancel/timeout 有 source=mw RUN_STATUS
cancel/timeout 后没有 PENDING/LEASED task
Harness 重启后 attempt >= 2
```

## 5. 结论

```text
fault-matrix: PASS (5 scenarios)
```

说明：

- Harness 中途死亡不会再让 Run 永久卡住。
- MW 重启后运行中的 Run 能继续或重排。
- App 不在时工具失败可解释，Run 仍能收敛。
- 控制面 cancel/timeout 现在有可回放事件，队列也会清理。
