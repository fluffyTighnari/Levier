## 3. AppendEvent 规则

### 3.1 事务

`AppendEvent` 在单事务内：

1. `SELECT lease_epoch, last_event_attempt, last_event_seq FROM runs ... FOR UPDATE`
2. 校验 `Event.LeaseEpoch == runs.lease_epoch`
3. 计算 gap
4. `INSERT run_events ... ON CONFLICT DO NOTHING`
5. 仅在事件推进时更新 `runs.last_event_*`
6. Commit

崩溃时 INSERT 和投影要么都成功，要么都回滚。

### 3.2 旧 epoch

```text
Event.LeaseEpoch != runs.lease_epoch
  → AppendResult.Stale = true
  → 不插入
  → Control staleEvents++
```

### 3.3 乱序与缺口

```text
gap = event.seq - last_event_seq - 1
gap > 16  → AppendResult.Gap = true
```

- 乱序事件仍按 `(attempt, seq)` 插入。
- 投影只前进到更大的 `(attempt, seq)`，不回退。
- 迟到事件不会覆盖 `last_event_*`。
- gap 超过窗口时 Control `gapEvents++` 并记录日志，但继续写入。

### 3.4 ephemeral

- `Event.Ephemeral=true` 被 RunStore 拒绝：`ErrEphemeralEvent`。
- Control 在调用 RunStore 前直接分流：
  - 不落库
  - `ephemeralEvents++`
- 当前 AppHub 尚未实现，所以只计数，不转发。

### 3.5 source 与 seq 区间

```text
daemon: 1 <= seq < 1<<62
mw:     1<<62 <= seq < 1<<63
```

- daemon 事件使用保留区间会被拒绝。
- MW 事件使用 daemon 区间会被拒绝。

## 6. 风险与未完成

| 项 | 影响 | 处理 |
|---|---|---|
| 没有真正的内存重排缓冲区 | 乱序事件直接落库，靠 seq 排序 | 回放按 `(attempt,seq)`；窗口只用于 gap 判定 |
| 缺口没有超时补偿 | 永远缺失时只记一次 gap | 后续加入 gap 监控/对账 |
| ephemeral 只计数不转发 | token delta 实时流未接 | P7 AppHub/WS |
| stale/gap 计数只在单进程内存 | 多实例不聚合 | P8 指标 |
| MW 事件生成器尚未接入 | 只有区间校验 | P6 取消/超时事件 |
| `last_event_seq` 是最大 seq 而非连续水位 | gap 填补后仍保留最大值 | 补拉语义按最大值向后即可 |
| `AppendEvent` API 从 bool 改为结果结构 | 内部调用已适配 | 文档已更新 |
