## 1. 目标

daemon 重连时，MW 不能只看“daemon 是否连接”，还要看它实际报告了哪些 Run。
本步让每个 active Run 在 Hello 后都有明确去向：

```text
一致           保持
assigned 未上报 重排队
running 未上报  重排队
epoch 不一致    取消旧执行 + 重排队
terminal 仍上报 取消旧执行 + 失败 pending local tools
```

## 2. 改动

文件：`internal/control/lifecycle.go`

### 2.1 assigned / running 未上报

之前只处理 `running`。现在：

```text
run.Status == running
  → requeueRun

run.Status == assigned && assigned_at <= hello.connected_at
  → requeueRun
```

`assigned_at > connected_at` 的 Run 是 Hello 之后并发分配的新 Run，
不能当成丢失，否则会把刚分配的任务误重排。

新增辅助函数：

```go
func assignedBeforeHello(run runstore.Run, info connection.DaemonInfo) bool
```

### 2.2 epoch 不一致

之前只把 run_id 放进 Reconcile cancel 列表。现在：

```text
Reconcile(cancel old execution)
→ requeueRun
   → RequeueRun（epoch + 1）
   → hub.Release
   → cancelLocalTools(DAEMON_LOST)
   → Enqueue(RUN_RETRY)
```

### 2.3 terminal Run 仍被 daemon 报告

```text
Reconcile(cancel old execution)
→ cancelLocalTools(RUN_CANCELLED)
```

不重排队，避免已终态 Run 被重新执行。

### 2.4 TaskRetry 入队失败的补偿

`requeueRun` 已有：

```text
WARN control enqueue retry failed
```

下一次同一 daemon 的 Hello 会执行 `scheduleQueuedRuns`，
把仍为 queued 的 Run 重新入队，因此不依赖单次 Enqueue 成功。

## 3. 测试

新增 4 个 `TestReconcileDaemonCases` 子用例：

```text
assigned run missing from hello requeues
assigned after hello is left alone
epoch mismatch requeues and fails tools
terminal run reported cancels tools
```

断言：

```text
assigned 未上报 → queued / epoch+1 / RUN_RETRY / DAEMON_LOST
Hello 后分配   → 保持 assigned / 不重排
epoch 不一致   → Reconcile + queued / epoch+1 / RUN_RETRY / DAEMON_LOST
terminal 上报  → Reconcile + RUN_CANCELLED / 不重排
```

## 5. 风险

| 项 | 影响 | 处理 |
|---|---|---|
| Hello 重排可能重复工具副作用 | normal runtime 是 at-least-once | 已在 `docs/MVP.md` 写明；App 按 invocation_id 幂等 |
| Reconcile 在 Hello 回调中同步做 DB 操作 | daemon 重连时延迟 | 当前单机 MVP 可接受；后续可异步化并限流 |
| `assigned_at` 与 `connected_at` 时钟 | 极端时钟回拨可能误判 | 同一 MW 进程内使用同一时钟，风险低 |
| 多 daemon 竞争 | 不在 MVP 范围 | 依赖 epoch fencing，后续做多 daemon 演练 |
