### 查询示例

```promql
# Run 完成速率
sum(rate(mw_runs_total{status="completed"}[5m]))

# 工具错误率
sum(rate(mw_tool_invocations_total{status="error"}[5m]))
/
sum(rate(mw_tool_invocations_total[5m]))

# P95 工具耗时
histogram_quantile(0.95, sum by (le, tool) (rate(mw_tool_duration_seconds_bucket[5m])))

# HTTP 5xx
sum(rate(mw_http_requests_total{status=~"5.."}[5m]))

# 队列积压与最老任务
sum(mw_workflow_tasks{status="PENDING"})
max(mw_workflow_task_age_seconds)

# Daemon 容量利用率
sum(mw_daemon_capacity{kind="used"}) / sum(mw_daemon_capacity{kind="total"})

# 事件丢弃
sum by (reason) (rate(mw_events_dropped_total[5m]))
```

## 4. Trace 与日志

- `X-Request-ID` → `runs.trace_id` → `TaskAssign.trace_context`。
- 请求日志字段：

```json
{
  "msg": "http request",
  "request_id": "...",
  "method": "POST",
  "route": "POST /api/v1/runs",
  "status": 202,
  "duration_ms": 12,
  "remote_addr": "127.0.0.1:52111"
}
```

- 分配与终态日志带：

```text
run_id, trace_id, app_id, attempt, lease_epoch, daemon_id, runtime, strategy
```

- WS 连接/断开日志带 `app_id`、`remote_addr`、`duration_ms`。
- 工具持久化失败日志带 `run_id`、`invocation_id`。

- 当前日志不打印请求头、API key、ws_token、secret 或 executor 配置。

## 7. 未完成与风险

| 项 | 影响 | 处理 |
|---|---|---|
| 没有 OpenTelemetry span/exporter | 只能按 trace_id 关联日志/指标 | 后续接 OTLP 或保留 v1 trace_id 方案 |
| Workflow claim/handler 是平均耗时 gauge | 无法算分位数 | 后续改为直方图 |
| `/metrics` 未鉴权 | 指标可被任意访问 | 生产应由网关/内网限制 |
| 指标为单进程 | 多实例需 Prometheus 聚合 | P8 多实例 |
| 没有 Grafana 仪表盘文件 | 只能手工 PromQL | 后续提供 dashboard JSON |
| 没有自动 PII 扫描 | 依赖代码不打印敏感字段 | 后续加日志 lint/扫描 |
| 部分标签可能高基数 | app/daemon/tool 数量增长 | 生产限制基数或聚合 |
