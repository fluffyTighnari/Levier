## 3. 关键决策

- 使用 `grpc.aio` 单条双向流；一个 reader 循环 + 一个 writer 循环。
- `ChannelClient` 维护 `asyncio.Queue` 出站队列，容量 256；队列满时等待，形成背压。
- Hello 在每次新连接建立后直接写入，作为该 stream 的第一条消息。
- 心跳默认 10s，通过出站队列发送不影响 reader。
- 重连指数退避：初始 1s，上限 30s，带 0.8–1.2 抖动。
- 入站消息交给可注入的 `on_message`；支持同步或异步 handler。
- `ChannelClient.stop()` 取消 stream/runner 并关闭 channel。
- `running_runs` 和 `running_count` 通过回调注入，P3-25 接真实任务状态。
- ULID 本地生成，不新增 Python 依赖。

## 5. 风险与未完成

| 项 | 影响 | 处理 |
|---|---|---|
| 没有 TaskAssign/Cancel/Reconcile 业务处理 | 收到消息只记日志 | P3-25 |
| 没有认证失败分支 | 错误 token 会不断重连 | P3-25/P3-26 加 AUTH_FAILED 停止策略 |
| TLS 只使用系统根证书 | 没有自定义 CA/mTLS | 后续配置扩展 |
| 出站队列跨重连保留 | 旧消息可能在新连接发送 | 后续可按 run/epoch 过滤 |
| 心跳是固定 10s | 未从配置读取 | P3-25 前后补配置项 |
| `running_runs` 仍为空 | 重连对账还不可用 | P3-25 接 RunManager |
