## 1. 目标

成功 HTTP 请求也要在默认 INFO 级别可见，否则排障时只能看到错误。

## 2. 改动

`internal/httpapi/observability.go`：

```text
默认 INFO
5xx → WARN
/healthz、/readyz → DEBUG
/metrics → 不记录
```

保留字段：

```text
request_id / method / route / status / duration_ms / remote_addr
```

## 3. 测试

新增：

```text
TestSuccessfulAPIRequestIsLoggedAtInfo
```

断言：

```text
POST /api/v1/runs 成功 → level=INFO + route=POST /api/v1/runs
GET /healthz          → 不是 INFO（探针不刷访问日志）
```

## 5. 风险

| 项 | 影响 | 处理 |
|---|---|---|
| 日志量增加 | 每次 API 请求一条 INFO | MVP 单机可接受；高流量时再采样/降级 |
| 探针日志 | 默认 DEBUG 不输出 | 需要时调低日志级别 |
| route 使用 `r.Pattern` | 未匹配路由为 `unmatched` | 明确标记，便于发现扫描/错误路径 |
