## MCP references

### 1. How to declare

Written when initializing the project:

```sh
levier init --mcp-ref echo
```

Multiple references:

```sh
levier init --mcp-ref echo,github
```

In code:

```python
app = App(tools=[counter_add], mcp=["echo", "github"])
```

Or via environment variable:

```sh
export LEVIER_APP_MCP_REFS=echo,github
```

### 2. Who handles the connection

```text
App          declares references only
Levier       stores MCP servers and allowed_tools
MCP Runtime  connects to MCP servers, resolves secrets
Runtime      uses tools through ctx.toolbox()
```

App code does not implement an MCP client, and does not store MCP server keys.

### 3. References must be registered

```sh
levier mcp add \
  --name echo \
  --transport stdio \
  --config-file ./examples/mcp_echo/config.json
```

An unregistered reference makes App initialization or connection fail.

### 4. Tool naming

On the model side:

```text
mcp__<server>__<tool>
```

For example:

```text
mcp__echo__echo_token
```

The name is generated by the MCP Runtime; the App and the Runtime do not need to concatenate it by hand.

### 5. Troubleshooting

| Symptom | Check first |
|---|---|
| App connection fails | Whether `mcp_ref` is registered |
| The model does not see the tool | Whether `allowed_tools` includes the tool |
| `SECRET_MISSING` | Whether `${secret:name}` has a value |
| `TOOL_DENIED` | The tool is not in the allowlist |
| `MCP_RUNTIME_UNAVAILABLE` | Whether the shared MCP Runtime is running |

## Errors and reconnects

### 1. ToolExecutionError

A handler can raise a structured error on its own:

```python
from levier import ToolExecutionError


@tool
def my_tool(value: str) -> dict:
    if not value:
        raise ToolExecutionError("BAD_INPUT", "value is required")
    return {"ok": True}
```

The SDK turns it into an error result in `TOOL_CALL_END` and does not let the WebSocket crash.

### 2. Common error codes

| code | Meaning | What to do first |
|---|---|---|
| `UNAUTHORIZED` | Wrong App key or admin token | Re-run `levier init` or check the token |
| `TOOL_NOT_FOUND` | The App has not registered this tool | Confirm the tool name and that the process is online |
| `TOOL_TIMEOUT` | Tool execution timed out | Check handler logs and raise the timeout |
| `TOOL_EXEC_ERROR` | The handler raised an exception | Check the App process logs |
| `APP_UNREACHABLE` | The App disconnected; pending tools failed | Restart the App and resubmit |
| `MODEL_PROVIDER_NOT_FOUND` | The provider is not registered | `levier model connect` |
| `SECRET_MISSING` | The model secret is not configured | Reconnect, or check the secret file |

### 3. Disconnects and reconnects

When the App disconnects:

```text
The run does not pause
Pending local tools fail with APP_UNREACHABLE
After the App reconnects it can accept new tool calls
```

The SDK handles WebSocket reconnection; your code only needs to keep the process alive.

`levier dev` must stay running. For one-off cases use:

```sh
levier run "..." --with-app
```

### 4. Locating events

```sh
levier run show <run_id> --events
```

Focus on:

```text
TOOL_CALL_BEGIN
TOOL_CALL_END
ERROR
```

### 5. SDK exception types

```text
ToolExecutionError   tool business error
AppInactiveError     App unavailable
HTTPError            HTTP/API error
ProtocolError        protocol error
TransportError       connection/transport error
```

Read the structured code first; do not parse display text.
